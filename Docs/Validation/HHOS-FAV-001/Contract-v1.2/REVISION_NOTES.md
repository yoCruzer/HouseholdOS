# v1.2 复审与迁移说明

日期：2026-09-28。基于实际解压读取v1.1、远端仓库检查及当前官方资料。尚未运行任何HouseholdOS平台验证，也没有Medium/High同任务对照结果。

## 为什么更新

v1.1已覆盖大量关键漏洞，不能描述为“全部错误”。这次主要做减法和归并，避免模型把每个风险都实现成独立子系统；同时补齐少量跨边界漏洞。一个Program/独立worktree/保护既有修改/最小审批/影响驱动测试/证据分级继续有效。

## 改动

1. 默认模型从Astra High改Medium；高推理非启动/过gate条件，也不因普通失败频繁请求用户切档。
2. 按最小真实链路推进，再注入关键故障；fake与live共享实际codec/reducer，防止只测了一份理想实现。
3. 明确最小代码范围与结束：验证结论、可复用/应丢弃代码及正式实现地图；不提前做全功能sync/backup产品。
4. 原Mac路径/两份String Catalog是历史提示；恢复当前已存在的worktree、旧版Program成果/有效证据，不重复开工。
5. outbox仍是意图真源，但不硬指定某个engine pending接法。派生调度状态可重建即可，不为“单一真源”徒增桥接复杂度。
6. Media identity / Photos源 / representation revision / protective copy分开；补旧媒体请求晚到、源图变化与安全副本不能偷偷升级上云政策。
7. 降媒体同步档/OFF与清除云副本分开；不得许诺立刻腾出iCloud空间。
8. 系统备份排除改为保守默认与策略决定，动态按云状态切换延期；不以一次上传ACK代替持续可恢复性。
9. 补受保护文件暂不可用≠损坏、独立库根身份、DB/media完整generation切换、备份中未解决冲突的范围诚实。
10. 冻结逐决策、逐平台证据；不制造“所有底层问题已经解决”的总绿标。现有小规模live预算改累计，避免重启run绕过预算。
